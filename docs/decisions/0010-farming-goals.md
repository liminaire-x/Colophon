# 0010 — 수확·번식 목표, 지급품, 수락 뒤 대사

2026-09-26 · 세 번째 이야기(농부의 밭) 설계(구현 전) · 고치는 비용: **비쌈** (퀘스트 문서·플레이어 기록에 남는다.
첫 공개 전이라 지금은 초기화로 쌈)

## 방향: "직접 해보기"는 행동을 센다

농부는 밀을 원하는 게 아니라 플레이어가 **직접 길러 보기**를 원한다. 제출형(`item`)은 창고의 밀 64개로 바로 끝나므로,
늑대 사냥의 처치형(`kill`)처럼 **퀘스트를 받은 뒤 자기 손으로 한 행동**을 센다.

목표는 여전히 한 목록이라 섞어 걸 수 있다. 엄격한 퀘스트는 "감자 10포기 수확 + 감자 20개 제출"처럼 둘을 함께 건다
(제출형은 어디서 난 감자든 센다).

## 수확형 목표

```json
"goals": [ { "harvest": "minecraft:wheat", "count": 10 } ]
```

- **작물 블록 id**를 적는다(감자는 `minecraft:potatoes`, 아이템 `minecraft:potato`가 아님). 캐는 대상이 블록이고, 처치형이
  몹 id를 적는 것과 같다. 아이템으로 적으면 밀은 "밀"인지 "밀 씨앗"인지 애매하다. 작가는 에디터의 작물 목록에서 고른다.
- **포기 수**로 센다. 한 포기에서 감자가 몇 개 나오든 1. 행운에 따라 진행이 들쭉날쭉하지 않고, "직접 한 행동"에 맞다.
- **받는 작물**: "다 자람"이 게임에 분명한 것만. 바닐라 작물 틀(`CropBlock`: 밀·당근·감자·비트, 같은 틀을 쓰는 모드
  작물), 네더 사마귀, 코코아. 그 밖은 publish 거부(**보류**, 나중에 아이디어를 낸다): 호박·수박(블록이 열매, 단계 없음),
  사탕수수·선인장·대나무(위로 자랄 뿐), 달콤한 열매 덤불(캐지 않고 우클릭으로 땀). 나중에 받게 되어도 옛 문서는 안 깨진다.
- 세는 규칙(게임 코드, 쌈):
  - 다 자란 것만. 덜 자란 것은 안 센다.
  - **캔 플레이어만**. 물·피스톤처럼 캔 사람이 없는 수확은 안 센다(마인크래프트 `Block.dropResources`의 캔 사람 없는 경로).
  - 캔 순간만 본다: 퀘스트를 받기 전에 심은 것, 뼈가루로 키운 것, 남(다른 플레이어·마을)이 심은 것도 센다. 안 세려면
    "누가 심었나"를 밭 한 칸마다 저장해야 해서 비싸다.
  - 처치형과 같이 **진행 중일 때만**, **목표 수까지만**, 다른 모드가 취소하면 안 센다.
  - 신호(쌈): NeoForge `BlockEvent.BreakEvent`를 가장 늦게, 취소되지 않았을 때만 듣는다. 플레이어가 캘 때만 오고
    (`ServerPlayerGameMode.destroyBlock`), 캐기 전 상태가 담겨 다 자랐는지 볼 수 있다. 모험 모드처럼 캘 수 없는 경우는
    이미 취소되어 온다. **크리에이티브 모드로 캐도 센다**(아이템이 떨어지지 않아도 캔 행동). `BlockDropsEvent`는
    크리에이티브에서 안 오고 폭발처럼 플레이어가 아닌 캔 쪽도 와서 고르지 않았다.
  - 에디터는 게임에서 작물 목록을 받아 고르게 한다(`GET /api/crops`, 다른 모드 작물 포함). 퀘스트 화면 아이콘은 그
    작물을 집을 때 나오는 것(밀 씨앗, 감자, 코코아 콩 …), 이름은 블록 이름("Wheat Crops").

## 번식형 목표

```json
"goals": [ { "breed": "minecraft:cow", "count": 2 } ]
```

- **몹 id**, **태어난 새끼 수**로 센다.
- **먹이를 준 플레이어 모두**: 부모 두 마리에게 각각 먹인 사람을 확인한다(`Animal.getLoveCause`). 둘이 한 마리씩 먹였으면
  둘 다 센다. 바닐라 통계(`animals_bred`)는 한 명에게만 쳐 주지만 두 사람 모두 직접 했다.
- 받기 전에 먹여 두고 받은 뒤 태어나도 센다(태어난 순간만 본다). 먹인 사람이 없는 번식(다른 모드의 자동 장치 등),
  다른 모드가 취소한 번식(`BabyEntitySpawnEvent`는 취소 가능)은 안 센다. 진행 중일 때만, 목표 수까지만.
- **받는 동물**: 번식하면 새끼가 바로 태어나는 동물(`Animal.spawnChildFromBreeding` → `BabyEntitySpawnEvent`). 알을 낳는
  동물(거북·개구리·스니퍼: NeoForge 소스에서 개구리·스니퍼는 번식 처리를 덮어쓰고, 거북은 자기 알 낳기 동작을 쓴다)과
  주민(먹이가 아닌 다른 체계)은 publish 거부(**보류**).
- 구현(쌈): **태어난 새끼의 종류**로 센다(말 + 당나귀 → 노새면 `breed: minecraft:mule`). 게임은 몹을 만들어 봐야 종류를
  알 수 있어서, publish 검사와 에디터 동물 목록(`GET /api/animals`)은 월드에 넣지 않는 몹을 한 번씩 만들어 본다(`Breeding`).

## 진행 기록 키: `<종류>:<대상 id>`

```
key   progress_<퀘스트 id>
value {"kill:minecraft:wolf": 2, "breed:minecraft:cow": 1, "harvest:minecraft:wheat": 3}
```

- [0005](0005-quests.md)의 몹 id만 쓰던 키(`{"minecraft:wolf": 2}`)를 **대체**한다. 한 퀘스트에 "소 처치 + 소 번식"을
  걸어도 숫자가 섞이지 않는다.
- 처치까지 **모두** 표시를 붙인다(사용자 결정: 종류별로 걸러 보기 쉽다). 새 종류에만 붙이면 초기화가 없었지만 규칙이 둘이 된다.
- 기록 모양이 바뀌므로 **조각 1을 올리기 전에 `reset`**(변환 코드 없음, CLAUDE.md 개발 단계 규칙).
- 한 퀘스트에 **같은 종류·같은 대상**은 하나만(0005의 "같은 몹 처치 목표는 하나" 확장).

## 지급품 (`supplies`)

```json
"supplies": [ { "item": "minecraft:wheat_seeds", "count": 5 } ]
```

- 퀘스트를 하라고 **받을 때 주는 물건**. 보상(`rewards`)과 모양이 같다(`/give` 문법, ✋ 버튼, [0006](0006-item-syntax.md)).
- **퀘스트가 진행 중이 되는 순간** 준다. 대화창의 [수락]이든 그래프의 `Reveal Quest`든 같다. 숨김 → 진행 중은 한 번뿐이라
  **한 번만** 받는다. 수락 즉시(대사 전) 줘서 대사 도중 창을 닫아도 못 받는 일이 없다. 가방이 꽉 차면 발밑(보상과 같음).
- 완료할 때 되가져가지 않는다. 되가져가야 하는 물건(편지 등)은 제출형 목표로 건다.
- 제안 카드에 "받는 것" 줄을 더한다(화면, 쌈).
- 숙제: 나중에 "퀘스트 포기 → 다시 받기"가 생기면 다시 받을 때 또 주는지 그때 정한다.
- 이 이야기는 씨앗을 풀에서 얻을 수 있어 꼭 필요하진 않았지만, "편지를 전해 주게"처럼 NPC만 줄 수 있는 물건이 필요한
  이야기에 쓰려고 넣었다(사용자 결정).

## 수락 뒤 대사 (`lines.accepted`)

```json
"lines": { "offer": [...], "accepted": ["자, 이 씨앗으로 시작하게."], "active": [...], "complete": [...] }
```

- 다른 대사처럼 배열, 줄마다 애니메이션 가능([0009](0009-quest-workbench.md)). [수락] → 지급품 → `accepted` 페이지 → 다음
  용건 또는 창 닫힘. 비면 지금처럼 바로 넘어간다.
- 거절 뒤·완료 뒤 대사는 이야기가 요구할 때(roadmap 후보).

두 칸(`supplies`, `accepted`)은 없어도 되는 칸이라 옛 퀘스트 문서는 그대로 읽힌다(형식 번호 1 그대로).

## 고르지 않은 것

- **제출형 "밀 10개"만**: 창고 밀로 끝나 "직접 해보기"가 안 된다.
- **퀘스트 전용 아이템**(메이플식, 사용자 아이디어): 친구에게 넘겨받을 수 있어 "직접"이 느슨하다. 물건 자체가 이야기인
  퀘스트용으로 roadmap 후보에 남김.
- **나온 아이템 수로 세기**: 행운 곡괭이 등에 따라 속도가 크게 달라진다.
- **작물을 아이템 id로**: 익숙하지만 밀/밀 씨앗처럼 애매하다.
- **새 종류에만 키 표시**: 초기화가 없지만 규칙이 둘이다.
- **누가 심었나 기록**: 밭 한 칸마다 저장해야 한다.
