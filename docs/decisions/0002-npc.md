# 0002 — NPC: 정의와 배치

2026-09-23 · 조각 2 · 고치는 비용: **비쌈** (디스크와 월드에 남는다)

메이플스토리 방식이다. NPC **정의는 한 번**, **배치는 여러 곳**. 모든 배치가 정의를 공유한다.

## NPC 정의 (`config/colophon/npcs.json`, format 1)

```json
{ "format": 1, "npcs": [ { "id": "npc_7ha2m0qe", "name": "촌장" } ] }
```

- 에디터에서 등록하고 publish한다. `id`는 에디터가 붙이고 불변이라([0004](0004-ids-and-record-keys.md)) 그래프가 가리킨다. `name`은 머리 위에 보이는 표시용이다.
- **그래프 문서와 파일이 다르고, 형식 번호도 따로다.** NPC가 외형·애니메이션·시네마틱으로 커져도 그래프 문서는 건드리지 않는다.
- **publish는 두 문서를 한 번에** 보낸다(`{"graphs": …, "npcs": …}`). 함께 검사하고, 그래프가 없는 NPC를 가리키면 둘 다 거부한다.

## NPC 배치 (기록 DB, 주인 = 이 서버)

```
key   placement_<엔티티 UUID>   (처음엔 npc:<UUID>, 0004에서 바뀜)
value {"npc":"npc_7ha2m0qe","dim":"minecraft:overworld","x":1.5,"y":64.0,"z":-3.5}
```

- 게임에서 `/colophon npc spawn <id>`를 하면 내가 선 자리에 배치가 하나 늘어난다.
- **기록이 원본이다.** 엔티티는 1초마다 자기 배치 기록과 정의가 있는지 확인하고, 없으면 사라진다. 이 규칙 하나로 `remove` 명령어, 에디터에서 정의 삭제, 그 사이 언로드돼 있던 청크의 엔티티가 모두 처리된다.
- `/kill` 등으로 엔티티가 영영 사라지면 배치 기록도 지운다.

## 엔티티 `colophon:npc`

- 종류 이름은 월드에 저장되니 바꾸지 않는다.
- 무적(무적을 무시하는 피해만 통과: `/kill`, 공허), 움직이지 않고, 밀리지 않고, 디스폰되지 않는다.
- 조각 2의 모습은 임시로 스티브다. 조각 3에서 GeckoLib으로 바꾼다(비용 쌈).

## 서버 이름 (`config/colophon-common.toml` → `serverName`, 기본 `main`)

- 서버 기록의 주인이 `server:<이름>`이 된다. 여러 서버가 한 DB를 공유해도 기록이 섞이지 않는다.
- 이름을 바꾸면 그 서버의 옛 기록이 안 보이게 된다.

## 고르지 않은 것

- **명령어로 소환하면 NPC가 생기는 방식**: 정의를 에디터에서 먼저 만드는 편이 콘텐츠(작성) / 상태(플레이)의 구분과 맞는다.
- **NPC당 배치 하나(다시 소환하면 옮기기)**: 여러 배치가 더 단순하고 더 쓸모 있다.
- **배치를 월드 파일(SavedData)에**: 소유자가 멀티서버를 염두에 두고 기록 DB를 골랐다.
- **정의를 그래프 문서 안에**: 소유자가 NPC의 확장을 염두에 두고 별도 문서를 골랐다.
