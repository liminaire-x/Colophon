# 0004 — id와 기록 키

2026-09-23 · 조각 4 준비 · 고치는 비용: **비쌈** (문서·기록 DB가 가리킨다)

## id: `<종류>_<무작위>`

| 종류 | 예 |
|---|---|
| 그래프 | `graph_p4x81czt` |
| 노드 | `node_k3f9x2ma` |
| NPC | `npc_7ha2m0qe` |

- **에디터가 만들 때 무작위 8자(a-z, 0-9)로 붙이고, 아무도 고치지 않는다.** 사람은 이름(`name`)만 쓴다.
- **형식이 접두사를 강제한다**(`Ids.java`). 규칙: `<종류>_` 뒤에 a-z, 0-9. 손으로 쓴 파일의 `npc_chief`도 통과하지만 에디터는 그렇게 만들지 않는다.
- 접두사 덕분에 파일·기록·로그 어디서 보든 id가 무엇의 것인지 안다.
- 명령어(`/colophon npc spawn <id>`)는 Tab 자동완성이 NPC 이름을 툴팁으로 보여준다.
- 새 종류(퀘스트 등)는 같은 규칙으로 접두사만 추가한다.

## 기록 키: `<종류>_…`

| 기록 | 주인 | 키 |
|---|---|---|
| 표식 | 플레이어 | `flag_greeted` (`flag_` + 표식 이름) |
| NPC 배치 | 서버 | `placement_<엔티티 UUID>` |

- 모든 키가 종류 접두사로 시작하므로 서로 겹치지 않는다. 0001의 `종류:` 규칙을 대신한다.
- 배치는 NPC id(`npc_…`)와 헷갈리지 않게 `placement_`다.
- id가 이미 종류를 담고 있으면 **id 자체를 키로** 쓸 수 있다(예: 퀘스트 상태).

## 옛 데이터

개발 단계라 변환 코드 없이 로컬 데이터(`run/config/colophon/`의 `graphs.json`, `npcs.json`, `records.mv.db`)를 초기화했다.
첫 공개 이후에는 형식 번호를 올리고 변환 코드를 쓴다(0001).

## 고르지 않은 것

- **사람이 짓는 id**(지금까지): 영어 이름을 따로 지어야 하고, 마음에 안 들어도 못 바꾼다.
- **접두사를 에디터 기본값으로만**: 강제하지 않으면 id만 보고 종류를 확신할 수 없어 기록 키에서 종류를 뗄 수 없다.
- **처음 publish 전까지 id 편집 허용**: 소유자가 "변경 불가"를 택했다. 경로가 하나라 단순하다.
- **노드 id는 짧게(`n1`)**: 소유자가 규칙을 하나로 맞추는 쪽을 택했다.
