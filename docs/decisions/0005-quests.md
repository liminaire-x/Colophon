# 0005 — 퀘스트: 정의, 상태, 공개

2026-09-23 · 조각 4 · 고치는 비용: **비쌈** (문서·기록 DB에 남는다)

## 퀘스트 정의 (`config/colophon/quests.json`, format 1)

```json
{ "format": 1, "quests": [ {
  "id": "quest_k3f9x2ma", "title": "밀 배달", "icon": "minecraft:wheat",
  "text": "촌장에게 밀 10개를 가져다주자.",
  "goals":   [ { "item": "minecraft:wheat",   "count": 10 } ],
  "rewards": [ { "item": "minecraft:emerald", "count": 5 } ]
} ] }
```

- NPC처럼 **에디터에서 작성하는 별도 문서**다. 형식 번호도 따로. publish는 세 문서(`graphs`, `npcs`, `quests`)를 한 번에 보내고 함께 검사한다.
- id는 `quest_<무작위>`([0004](0004-ids-and-record-keys.md)). `title`·`icon`·`text`는 언제든 바꿔도 된다.
- **목표와 보상은 목록**이다. 지금은 하나씩이지만, 나중에 한 개짜리를 목록으로 바꾸면 형식 번호를 올려야 해서 처음부터 목록으로 뒀다.
- 목표는 **아이템 제출형**(인벤토리에 모두 있으면 제출 가능). `icon`이 비면 첫 목표의 아이템을 보여준다.
- publish 때 아이템 id가 이 게임에 실제로 있는지 확인한다(오타·빠진 모드 거부). 그래프가 없는 퀘스트를 가리켜도 거부한다.

## 퀘스트 상태 (기록 DB, 주인 = 플레이어)

```
key   quest_k3f9x2ma        (퀘스트 id가 그대로 키)
value active | done         (기록 없음 = 숨김)
```

- 상태는 넷(숨김 → 진행 중 → 제출 가능 → 완료)이지만 **저장은 둘**이다. "제출 가능"은 저장하지 않고 그 순간의 인벤토리로 계산한다(진행 중 + 목표 아이템이 다 있음). 플레이어가 밀을 버려도 기록이 어긋나지 않는다.
- 이 기록이 하는 일: **보상 중복 방지**(`done`), 그래프 분기(`Quest State` 노드), 재접속 때 무엇을 보여줄지.
- **퀘스트를 지워도 플레이어 기록은 남는다.** 같은 id로 다시 만들면 예전 상태가 돌아온다(시즌·이벤트 퀘스트에 쓸 수 있음).
- 그래프 `Quest State` 노드의 갈래 이름 `hidden` / `active` / `ready` / `done`은 그래프에 저장되니 바꾸지 않는다.

## 공개

- 서버는 **그 플레이어에게 공개된 퀘스트만** 보낸다(접속할 때, 공개될 때, publish 후). 공개 전엔 클라이언트에 아무것도 없다. FTB Quests는 로그인 때 퀘스트북 전체를 보내서(`ServerQuestFile.playerLoggedIn` → `SyncQuestsMessage`) 이 방식을 쓸 수 없었다.
- `Reveal Quest` 노드: 숨김이면 진행 중으로 바꾸고 보낸다. 이미 공개된 퀘스트엔 아무것도 하지 않는다(완료가 진행 중으로 되돌아가지 않게).
- 패킷은 공개된 퀘스트 전체를 매번 통째로 보낸다(비용 쌈. 퀘스트가 많아지면 바꾼다).

## 완료 (조각 5)

- `Complete Quest` 노드 하나가 **같은 순간에** 목표 아이템 회수 → 보상 지급 → 상태 `done` 기록 → 화면 갱신을 한다.
- 제출 가능이 아니면(숨김·진행 중·이미 완료) 아무것도 가져가거나 주지 않고, 그래프를 멈추며 로그를 남긴다. 갈래는 `next` 하나이고, 확인과 완료 사이에 틈이 생기는 노드(기다리기 등)가 오면 `not_ready` 갈래를 **추가**한다(옛 그래프는 안 깨짐).
- 목표는 **아이템 종류**로 센다(이름·인챈트 무관). 회수는 진행 계산(`countItem`)과 같은 칸에서 한다.
- 보상이 가방에 안 들어가면 **발밑에 떨어뜨린다**(`/give`와 같음, NeoForge `ItemHandlerHelper.giveItemToPlayer`).
- 플레이어가 나갈 때 기록을 바로 저장한다(0001). 게임은 인벤토리를 나갈 때 저장하므로, 그 사이 서버가 죽어도 보상과 `done`이 갈라지지 않는다.

## 퀘스트 화면 (비용 쌈)

- `J`(키 설정에서 바꿀 수 있음)로 열고 닫는다. 왼쪽 목록, 오른쪽 제목·본문·필요한 것(`밀 3/10`)·보상.
- 진행은 클라이언트가 자기 인벤토리를 세서 보여준다. 서버와 같은 계산(`Quests.hasGoals`)을 쓴다.

## 고르지 않은 것

- **FTB Quests**: 스토리 유출을 막을 수 없다(위).
- **"제출 가능"도 저장**: 인벤토리가 바뀌면 기록과 실제가 어긋난다.
- **상태 값을 JSON으로(`{"state":…}`)**: 누적 진행(처치 수 등)은 그런 이야기가 오면 다른 키로 추가해도 옛 기록이 깨지지 않는다.
- **퀘스트 정의를 NPC·그래프 문서 안에**: 0002와 같은 이유로 분리.
