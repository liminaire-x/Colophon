# 0008 — 폴더 (퀘스트, NPC, 그래프)

2026-09-25 · 작업대 1 퀘스트 탭(NPC·그래프는 같은 날 확장) · 고치는 비용: **비쌈** (문서에 남는다. 첫 공개 전이라 지금은 초기화로 쌈)

## 형식 (`quests.json`, format 1 그대로)

```json
{ "format": 1,
  "folders": [ { "id": "folder_2kq8d1xz", "name": "마을" },
               { "id": "folder_9fm3a0pe", "name": "촌장", "parent": "folder_2kq8d1xz" } ],
  "quests": [ { "id": "quest_k3f9x2ma", "title": "밀 배달", "folder": "folder_9fm3a0pe", ... } ] }
```

- 폴더는 **퀘스트 문서 안의 따로 된 목록**이다. 폴더도 id(`folder_<무작위>`, [0004](0004-ids-and-record-keys.md))를 받고, 퀘스트는 `folder`에 폴더 id만 적는다. 폴더 안의 폴더는 `parent`.
- `folders`, `parent`, `folder`는 모두 선택이다(없으면 맨 위). 옛 문서도 그대로 읽히므로 형식 번호는 1 그대로.
- publish 때 검사: 폴더 id 중복, 빈 이름, 없는 부모·폴더를 가리킴, 자기 안에 들어가는 고리(`a → b → a`).
- **폴더는 에디터 전용**이다. 게임(J 화면)은 쓰지 않고 클라이언트로 보내지도 않는다. 챕터처럼 보여줄지는 이야기가 요구할 때.
- 폴더를 지우면 안에 있던 퀘스트·폴더는 **한 단계 위로** 올라간다(아무것도 사라지지 않음). 에디터가 하는 일이라 비용 쌈.

## NPC·그래프에도 같은 방식 (2026-09-25 확장)

- `npcs.json`과 `graphs.json`도 **자기 문서 안에** 같은 모양의 `folders` 목록을 두고, NPC·그래프가 `folder`를 적는다.
  형식 번호는 둘 다 1 그대로(선택 칸이 늘었을 뿐).
- 세 문서의 폴더는 **서로 따로**다. 퀘스트의 "마을" 폴더와 NPC의 "마을" 폴더는 다른 폴더다. 한 문서의 폴더가 다른
  문서를 가리키지 않으니, 문서 하나만 읽어도 트리가 완성된다.
- 읽기·쓰기·검사는 한 곳(`Folders.java`), 에디터의 트리·폴더 편집도 한 곳(`FolderTree.jsx`)에서 세 문서가 함께 쓴다.
  규칙을 고치면 세 곳이 함께 바뀐다.

## 고르지 않은 것

- **퀘스트마다 경로 글자**(`"folder": "마을/촌장"`): 가장 단순하지만 빈 폴더를 둘 수 없다. 사용자가 원한 "폴더 만들기"와 맞지 않는다. 폴더 이름을 바꾸면 안의 퀘스트를 전부 고쳐야 한다.
- **브라우저에만 기억**: 형식은 안 바뀌지만 다른 PC·브라우저에서 폴더가 사라진다.
