## 다음 작업: 조각 4 "퀘스트 공개 + 퀘스트 화면"

목표(map.md 4~5번): 촌장을 우클릭하면 퀘스트 `밀 배달`이 **그 플레이어에게만** 공개되고, 퀘스트
화면에 아이콘·내용·필요한 것·보상과 `밀 3/10` 같은 진행이 보인다. **처음 만드는 클라이언트 화면**이다.

이미 정해진 것:
- FTB Quests 대신 **자체 퀘스트 화면**. FTB Quests는 로그인 때 퀘스트북 전체를 모든 클라이언트에
  보내서 스토리 유출을 막을 수 없다(소스 확인: `ServerQuestFile.playerLoggedIn` → `SyncQuestsMessage`).
- 핵심 개념은 **공개**: 서버가 공개된 콘텐츠만 그 플레이어에게 보낸다. 나중에 도감도 같은 방식.
- 퀘스트 상태: 숨김 → 진행 중 → 제출 가능 → 완료(플레이어별). 목표는 **아이템 제출형**(밀 × 10),
  보상은 에메랄드 × 5.
- 그래프 B(map.md)에 필요한 노드: 퀘스트 상태 4갈래 분기, 퀘스트 공개, 퀘스트 완료(회수 + 보상).

**먼저 사용자에게 선택지로 보여줄 비싼 결정** (구현 전에):
1. 퀘스트 정의를 어디서 작성하나: 웹 에디터 + 별도 문서(`quests.json`, `npcs.json`처럼 자체 형식 번호)가 자연스러운 후보.
2. 퀘스트 상태를 어떻게 저장하나: 기록 DB의 플레이어 주인, 키 `quest:<id>` 같은 접두사 규칙(표식은 `flag:`).
3. 퀘스트 id 규칙(a-z, 0-9, _, 불변)과, 그래프가 없는 퀘스트를 가리키면 publish 거부(`Catalog` 확장).

쌈(구현하며 정해도 됨): 화면 모양, 여는 키, 진행 표시 계산 위치, 서버→클라이언트 패킷 구조.

## 로컬 상태와 함정

- **Java는 에이전트 환경에서 컴파일하지 않는다.** CI와 사용자 IntelliJ로 확인한다. CI는
  `gh run view <id> --json conclusion` + 테스트 리포트의 실행 개수까지 본다.
- **커밋**: 사용자가 로컬에서 병행 편집한다. 커밋 전에 `git diff --cached --stat`를 보고,
  경로 지정 커밋(`git commit -- 파일`)을 쓴다. 커밋 끝에 공동 작성자 Claude 줄.
- GeckoLib은 사용자가 **4.9.3**으로 올렸다(`2f15aea`). decisions/0003의 "4.7"은 결정 당시 버전이다.
  API를 쓸 때는 4.9.3 소스로 확인할 것.
- `.claude/settings.local.json`은 개인 설정이라 커밋하지 않았다.
- 게임 데이터(`run/`, git 밖): `run/config/colophon/`에 `graphs.json`, `npcs.json`, `records.mv.db`.
  옛 v2 데이터는 `run/config/colophon/legacy-v2/`.
- 테스트 NPC 모델: `run/resourcepacks/colophon-test/`(git 밖, 에셋은 저장소에 넣지 않기로 함).
  원본 `source/chief.bbmodel`, 텍스처 스크립트 `source/chief-texture.mjs`.
- Blockbench MCP로 에셋을 만들 때는 [workflow.md](workflow.md)의 "에셋 작업"과 도구 특이점을 먼저 볼 것.
- 게임 쪽 문제는 **`run/logs/latest.log`부터** 본다.
