# Colophon 지도

> 이 문서는 Colophon을 **한 장에** 담는다. 개념을 쉬운 말로 정의하고, 첫 이야기가 그
> 개념들을 어떻게 지나가는지 보여준다. 새 개념은 **이야기가 요구할 때만** 여기에 추가한다.

## Colophon이 하는 일

마인크래프트 서버에서 일어나는 일을 **코드 대신 웹 에디터로** 만든다. 운영자는 NPC를
세우고, 퀘스트를 쓰고, "무슨 일이 생기면 무엇을 한다"를 노드로 잇는다. Publish하면
서버에 바로 반영된다.

Colophon은 **클라이언트+서버 모드**다. 플레이어도 설치한다(NPC 애니메이션과 퀘스트 화면
때문).

## 두 가지 재료: 로직과 콘텐츠

| | 로직 | 콘텐츠 |
|---|---|---|
| 무엇 | "X가 일어나면 Y를 한다" | NPC, 퀘스트 같은 **것** 자체 |
| 모양 | 그래프(노드를 선으로 이음) | 데이터(이름, 본문, 목표, 보상, 외형 …) |
| 예 | 촌장을 우클릭하면 퀘스트를 공개한다 | 퀘스트 `밀 배달`: 밀 10개를 가져오면 에메랄드 5개 |

로직은 콘텐츠를 **id로 가리키기만** 한다. 그래프가 "무엇을"까지 조립하지 않는다.
**그래프는 언제를, 콘텐츠는 무엇을** 맡는다.

## 개념

고치는 비용: **비쌈** = 디스크에 남거나 다른 곳이 가리킴 / **중간** / **쌈** = 내부 코드라 언제든 고침.

| 개념 | 쉬운 정의 | 비용 |
|---|---|---|
| id | 에디터가 붙이는 `<종류>_<무작위>` 이름표(예: `npc_7ha2m0qe`). 사람은 이름만 쓰고 id는 아무도 고치지 않는다. [decisions/0004](decisions/0004-ids-and-record-keys.md) | **비쌈** (다른 곳이 가리킴) |
| 그래프 | 트리거에서 시작해 행동으로 이어지는 노드 묶음. `id`(불변)와 `name`(표시)을 가진다 | 저장 형식은 비쌈([decisions/0001](decisions/0001-storage-format.md)), 나머지 쌈 |
| 트리거 | 그래프를 출발시키는 사건. 예: 플레이어 접속, NPC 우클릭 | 쌈 |
| 행동 | 그래프가 하는 일. 예: 채팅 보내기, 퀘스트 공개, 애니메이션 재생. 대상은 **이 사건의 플레이어** | 쌈 |
| 분기 | 상태에 따라 갈 길을 고른다. 예: 퀘스트 상태가 무엇인가 | 쌈 |
| 기록 | 주인(플레이어 / 서버 `server:<이름>`)에게 붙어 저장되는 값. 형식: [decisions/0001](decisions/0001-storage-format.md) | **저장 형식 비쌈** |
| 표식 | 플레이어에게 남기는 기록. 예: `greeted` | 중간 (이름이 저장에 남음) |
| NPC 정의 | 에디터에서 등록하는 NPC 콘텐츠: `id`(불변) + 표시 이름. `npcs.json`. [decisions/0002](decisions/0002-npc.md) | **id·형식 비쌈** |
| NPC 배치 | 정의 하나를 월드 여러 곳에 세운 것(메이플 방식). 게임에서 `/colophon npc spawn <id>`. 서버 기록에 저장되고, **기록이 원본**이라 엔티티는 기록을 따른다 | **저장 형식 비쌈** |
| 외형 | NPC의 모델·텍스처·애니메이션(GeckoLib). 정의의 `model`·`idle`이 리소스팩 파일을 이름으로 가리킨다. [decisions/0003](decisions/0003-npc-looks.md) | 중간 (리소스팩이 이름 규칙에 기댐) |
| 퀘스트 | 제목·아이콘·본문·목표·보상을 가진 콘텐츠. 에디터에서 작성, `quests.json`. [decisions/0005](decisions/0005-quests.md) | **id·형식 비쌈**, 내용은 쌈 |
| 퀘스트 상태 | 플레이어별: 숨김 → 진행 중 → 제출 가능 → 완료. 저장은 `active`·`done`뿐이고 "제출 가능"은 인벤토리로 계산 | **저장 형식 비쌈** |
| 공개 | 서버가 **그 플레이어에게만** 콘텐츠를 보낸다. 공개 전엔 클라이언트에 아무것도 없다 → 스토리 유출 방지 | 쌈 |
| 퀘스트 화면 | 공개된 퀘스트를 보여주는 클라이언트 화면. `J`로 연다 | 쌈 |

## 첫 이야기: 밀 배달

1. 플레이어가 **처음** 접속하면 채팅창에 인사말이 뜬다. (최초 1회)
2. 마을에 NPC `촌장`이 손을 내미는 애니메이션을 하고 서 있다. (운영자가 에디터에서 등록하고 게임에서 소환)
3. 촌장을 우클릭하면 채팅으로 말을 건다.
4. 퀘스트 화면에 `밀 배달` 아이콘이 나타난다. 누르면 내용·필요한 것·보상이 보인다.
5. 플레이어가 밀 10개를 모은다. 화면에 `밀 3/10`처럼 진행이 보인다.
6. 다시 촌장에게 말을 걸면 밀을 건네고 보상을 받는다. 촌장이 기뻐한다.

### 콘텐츠

- **NPC `촌장`**: 외형 = 모델 + 애니메이션 `손 내밀기`(반복), `기뻐하기`(1회).
- **퀘스트 `밀 배달`**: 목표 = 밀 × 10 (제출형), 보상 = 에메랄드 × 5.

### 그래프 A: 첫 인사

```
[플레이어 접속] → [이 플레이어에게 '인사함' 표식이 있나?]
    없음 → [채팅: "환영합니다"] → [표식 남기기: '인사함']
```

### 그래프 B: 촌장과 대화

```
[NPC 우클릭: 촌장] → [퀘스트 '밀 배달' 상태는?]
    숨김      → [채팅: "[촌장] 밀 10개만 구해다 주겠나?"] → [퀘스트 공개]
    진행 중   → [채팅: "[촌장] 아직 부족하구먼"]
    제출 가능 → [퀘스트 완료] → [애니메이션: 촌장 '기뻐하기'] → [채팅: "고맙네!"]
    완료      → [채팅: "[촌장] 덕분에 살았네"]
```

`퀘스트 완료` 한 칸이 밀을 회수하고 보상을 준다. 목표와 보상은 콘텐츠에 적혀 있다.
